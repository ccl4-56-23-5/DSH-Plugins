# 故障排查

| 现象 | 检查与处理 |
| --- | --- |
| 模型菜单没有供应商 | 在设置中开启供应商、勾选至少一个模型并保存；检查模型是否可用及凭据状态 |
| 搜索结果为空 | 清空条件，核对关键词；会话菜单仅搜索已启用模型，完整目录在模型管理中搜索 |
| Key框为空 | 已保存Key不会回显，留空会保留；看“已配置”状态，而非输入框内容 |
| 401/403 | 核对Key、账户权限、模型授权和供应商返回错误；不要公开截图中的密钥 |
| 404或重复`/v1` | 核对协议与基础地址，不填完整端点；API易OpenAI地址带`/v1`，Anthropic地址不带 |
| 同步目录失败 | 核对地址、协议、网络与Key；草稿地址变更需重新输入Key，也可手动添加确认过的模型ID |
| 目录有模型但回复失败 | 公开目录不代表账户权限，核对模型协议、参数、限制和具体错误 |
| 图标获取失败 | 核对供应商网站为公开HTTPS地址，检查代理/网络，点击“获取图标”；失败不影响模型配置 |
| 配置已被其他窗口修改 | 保存草稿内容，刷新最新配置后重新提交，避免覆盖其他窗口修改 |
| 模型配置只读 | 核对DSH挂载了可写settings与第三方模型服务，检查目标profile与DSH版本 |
| 设置页被侧栏挤压 | 确认安装2.1.0或以上并重启，检查已装文件是否与TGZ一致 |
| 来源无法删除 | 只允许删除本插件创建的来源；先将默认模型切到其他来源 |
| Ollama提示没有Key | 某些DSH适配器要求非空值，可为免认证本机来源填写占位值`ollama` |
| 离线安装缺依赖 | 原profile的其他依赖可能不在缓存；保留备份，按DSH正常维护流程补齐依赖后重试 |
| SHA-256不一致 | 重新从可信发行位置下载匹配版本，禁止修改清单来掩盖不一致 |

提交Issue时提供插件/DSH/Node版本、安装方式、复现步骤和脱敏错误。静态测试通过不能替代实际桌面或供应商回复验证；若问题仅在真实请求中出现，应说明所用协议与模型ID，隐藏Key和个人聊天内容。
